# Dream OS MVP 页面与交互冻结基线 v1.1

**状态：** READY FOR BUILD  
**冻结日期：** 2026-08-08  
**适用范围：** 首版移动端 App  
**原型依据：** `05_UX/prototype/index.html`  
**状态与数据依据：** `MVP_SCOPE_AND_STATE_MACHINE_v1.0.md`

## 1. 冻结目标

首版只验证一条最小闭环：

```text
记录梦境 → 存档 → 选择是否理解 → 澄清对话 → 查看阶段性理解 → 用户反馈
```

本文件是 UI 和交互的范围边界。新增页面、入口或状态，必须先更新本文件，再进入开发。

## 2. 首版必须实现的页面

| 页面 / 状态 | 用户任务 | 首版必须有 | 首版不做 |
|---|---|---|---|
| 首页 | 开始记录 | 昵称、简短引导、一个“记录梦境”主按钮、历史抽屉入口 | 最近梦境信息流、复杂状态卡、键盘入口 |
| 记录梦境 | 快速留下原始梦境 | 统一便签、年月日时间、默认文字输入、语音转写、返回、存档 | 画图、标签编辑、旧梦编辑 |
| 存档确认 | 决定下一步 | 同一张梦境便签、“现在理解”“只保存，不解梦” | 自动开始分析、额外红点 |
| 理解 | 查看当前状态并找到待理解梦 | 近期状态、历史变化入口、最新待理解梦、“开始理解” | 空白等待页、强制分析 |
| 理解会话 | 澄清一个梦 | AI 对话流、顶部进度条、纵向选项、自由文字、语音回答、自动保存 | 预先选择理解焦点、暂停按钮、多分支会话 |
| 理解结果 | 判断是否贴近 | 一句话核心理解、一条不确定、一条依据入口、三个纵向操作 | 长篇解梦文章、四个以上行动项、完成补充按钮 |
| 梦境 | 找回原始记录 | 可滚动历史卡片、标题、完整日期、原样内容、理解状态、日历、长按删除 | 历史梦补充/编辑、复杂搜索、红点提醒 |
| 梦境日历 | 按日期回看 | 有记录日期圆点、点击后展示当天梦境 | 直接展示心理结论 |
| 自我 | 查看长期积累 | 可读的梦图谱节点、节点详情、近期状态与历史变化 | 自由编辑图谱、复杂人格画像、自动诊断 |
| 历史抽屉 | 找回已完成对话 | 账号摘要、梦境数量、已完成理解、历史对话详情、返回抽屉 | 独立社交、消息系统、复制一套梦境正文 |

原型中的 `Onboarding`、`Demo`、`Partial Match`、`Readiness Result`、`Symbol Detail` 等页面只作为演示状态或内部验收入口，不作为首版独立导航页面。

## 3. 冻结的关键交互规则

### 3.1 记录

- 首页只有一个核心动作：“记录梦境”。
- 点击后直接进入便签，默认聚焦文字输入；语音是同一输入器内的次入口。
- 文字和语音转写都写入同一个原始记录，不能被 AI 摘要覆盖。
- 便签有时间但未存档前不显示标题；有内容后才显示便签外部的“存档梦境”。
- 左上角返回保留本地草稿；返回不归档、不删除。
- 语音状态必须明确显示“转写中 · 分:秒”和停止动作；结束后仍可继续打字。

### 3.2 存档与理解入口

- 存档时生成描述性标题，保存原始文字、转写和语音引用。
- 存档后显示同一张梦境便签，并询问是否现在开始理解。
- “现在理解”才创建该梦唯一的 Understanding Session。
- “只保存，不解梦”只改变状态，不生成心理结论；之后可从“理解”进入。
- 保存完成不显示 Dreams 红点，也不自动开始分析。

### 3.3 理解会话

- AI 根据梦境中最明确、可验证的体验直接提出第一个问题，不要求用户先选分析焦点。
- 一次只推进一个问题；候选项纵向排列，每行包含详细描述和右侧选择器。
- 候选项、自由文字和语音回答进入同一会话上下文。
- 用户离开后自动保存，下次进入恢复问题、回答和进度。
- 会话中不提供暂停按钮；返回即保存草稿并回到理解入口/历史。

### 3.4 结果与反馈

- 结果只保留核心理解、不确定点和依据；依据默认收起，点击后原地展开。
- 最多三个行动项，纵向排列：
  1. **很贴近**（主按钮）
  2. **不太像**（弱按钮）
  3. **补充**（弱按钮）
- “补充”在当前结果下展开 AI 对话，用户可打字或语音；不出现“完成补充”按钮。
- 只有“很贴近”才将本次理解标记为已确认并更新近期状态。
- “不太像”或部分确认保留为未确认草稿，不写入稳定个人理解。
- 所有结果都显示“阶段性理解，不是心理诊断”的边界文案。

### 3.5 历史与图谱

- Dream Record 在首页、存档确认、Dreams、日历和理解入口保持同一种便签样式。
- 当天梦境可显示理解入口；已完成理解的梦只显示“已理解”，不重复显示澄清入口。
- 历史梦不可补充或编辑；删除必须二次确认，并同步移除会话、日历索引和图谱证据关系。
- 梦图谱节点只读；点击节点查看“对你目前可能意味着什么”和可追溯梦境依据。

## 4. 首版明确不做

- 画图输入、跨梦手动编辑、复杂搜索和标签体系；
- 一个梦创建多个并列理解会话；
- 未成年人、监护人账户、家庭共享；
- 多地区危机资源库；
- 自动把单个梦或未经确认的假设写入长期个人理解；
- 图谱自由编辑、复杂人格画像和自动诊断；
- 推送、社交、分享和云端账号体系；
- 未经用户明确感知的历史梦境引用。

## 5. 开发验收闸门

进入下一阶段前，必须完成以下 P0 验收：

- [ ] 文字记录 → 存档 → 选择“现在理解”可完整跑通；
- [ ] 语音转写与文字输入写入同一条 Dream Record；
- [ ] 返回后草稿可恢复，存档前不出现在 Dreams；
- [ ] 理解会话离开后可恢复，且一梦一会话；
- [ ] 结果反馈只有“很贴近”才更新为已理解；
- [ ] Dreams、日历、理解状态和删除行为保持一致；
- [ ] 关键心理文案明确“阶段性、可修正、非诊断”；
- [ ] 单元测试通过后，再进行 3–5 名成年用户的真实可用性测试。

任何未列入本文件的功能，默认不属于 MVP，不得直接加入开发分支。
