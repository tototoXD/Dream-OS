# Dream OS MVP 可用性测试方案 v1.0

## 1. 测试目的

验证 Dream OS 的核心闭环是否能被第一次使用的成年人独立理解：

> 记录梦境 → 存档 → 判断是否适合理解 → 澄清式对话 → 形成阶段性理解 → 回到长期观察

本轮只验证交互是否清晰、状态是否可理解，不验证心理分析结论是否具有临床效度。

## 2. 测试对象

- 3–5 名成年人，年龄、职业和数字产品熟练度尽量有差异。
- 不要求参与者近期有清晰梦境，也不要求分享真实隐私。
- 排除当前处于明显心理危机、或不愿接触梦与心理话题的人。
- 测试记录使用虚构梦境；参与者可以随时跳过或停止。

## 3. 测试设置

### 原型准备

1. 打开 `05_UX/prototype/index.html`。
2. 每位参与者开始前，从原型顶部选择 `Onboarding / 新用户`。
3. 需要测试示例数据时，选择 `Demo / 示例数据`。
4. 记录屏幕、操作路径、停顿、误触和原话；不要只记录“完成 / 未完成”。

### 主持原则

- 不主动解释页面含义，不替参与者寻找按钮。
- 只在参与者连续 10 秒没有动作时问：“你现在在想什么？”
- 参与者询问“这里应该点什么”时回答：“你觉得哪个最符合你的理解？”
- 不评价参与者的梦，也不把原型中的理解说成心理诊断。
- 每项任务结束后再提问，不在操作过程中纠正。

## 4. 开场话术

> 今天想了解的是这个产品是否容易理解，不是在测试你。请把你想到的内容说出来，包括你为什么想点某个按钮。如果某一步让你不舒服，可以随时跳过。我们使用虚构梦境，不需要分享真实经历。

## 5. 测试任务

每项任务开始时只读出“任务目标”，不要读出操作步骤或预期答案。

### 任务 A：第一次记录一个梦片段

**任务目标**

> 你刚醒来，只记得“车、地下停车场、找不到出口”。请把这段梦记录下来并完成保存。

**观察点**

- 是否直接找到「记录梦境」入口。
- 是否理解记录不必完整。
- 是否点击输入框并使用键盘模拟输入。
- 是否知道「存档梦境」会结束记录并保存。

**通过标准**

- 60 秒内开始记录。
- 不需要主持人提示即可完成存档。
- 不把「存档梦境」理解成删除、发送给他人或开始分析。

### 任务 B：记录过短时是否理解“先保存”

**任务目标**

> 这次你只记得一个词：“车”。请完成记录，并告诉我你接下来会做什么。

**观察点**

- 是否理解系统为什么没有立即开始理解。
- 是否能说出“先记录更多”与“理解失败”的区别。
- 是否会误以为产品出错或数据丢失。

**通过标准**

- 能复述“现在证据还不够，先保存即可”。
- 不把“先记录更多”理解成必须马上补写完整梦境。

### 任务 C：对清晰梦境开始理解

**任务目标**

> 你记得一个比较清晰的梦：你在地下停车场找自己的车，车应该在 B2，但电梯里没有 B2 按钮，醒来后很着急。请记录它，并决定是否现在开始理解。

**观察点**

- 是否理解“现在理解”和“稍后理解”的差别。
- 是否看到梦境便签、时间和原样记录。
- 是否理解 AI 会先提问，而不是直接给出结论。

**通过标准**

- 能自主选择一个入口并说明理由。
- 能理解 AI 澄清过程是逐步进行的。

### 任务 D：中途离开后继续理解

**任务目标**

> 进入理解对话，回答一到两个问题后离开。现在请你从产品中找回刚才未完成的理解，并继续下去。

**观察点**

- 是否能在梦境卡片或历史入口找到“理解未完成”。
- 是否理解「继续理解」会回到上次位置。
- 是否会担心之前的回答丢失。

**通过标准**

- 90 秒内找到未完成会话。
- 能确认之前的回答和对话仍然存在。

### 任务 E：确认一次阶段性理解

**任务目标**

> 完成一次理解对话，查看 AI 的阶段性理解，并告诉我这份理解是否贴近你的感受。

**观察点**

- 是否知道“很贴近 / 不太像 / 补充”的差别。
- 是否把阶段性理解当成可修正内容，而不是最终诊断。
- 确认后是否能找到梦境状态和近期状态的更新。

**通过标准**

- 能独立完成反馈。
- 能说出理解结果来自梦境记录和自己的回答。
- 不认为 AI 已经“定义了自己”。

## 6. 任务后提问

每项任务完成后，选择 1–2 个问题询问：

- 你刚才认为这一步会发生什么？
- 哪个词或按钮让你最不确定？
- 你觉得这份内容是记录、建议，还是诊断？为什么？
- 如果现在不想理解，你觉得应该怎么做？

## 7. 结束访谈问题

1. 如果只能保留一个入口，你会保留哪个？
2. 你能用自己的话解释“梦境”“理解”“自我”三个页面的区别吗？
3. 你什么时候会愿意把真实梦境交给这个产品？什么时候不会？
4. 哪一处让你感到被理解，哪一处让你感到被解释？
5. 你是否担心梦境原文、语音或理解结果被别人看到？

严重级别定义：

- **P0**：无法记录、无法存档、无法继续理解，或把 AI 理解当成心理诊断。
- **P1**：核心路径可完成，但需要提示，或状态含义明显误解。
- **P2**：不影响完成任务的文案、视觉或效率问题。

## 9. MVP 通过标准

满足以下条件，才进入技术方案和开发排期：

- 至少 4/5 名参与者能在无提示下开始记录。
- 至少 4/5 名参与者能正确理解「存档梦境」。
- 至少 4/5 名参与者能区分“现在理解”和“稍后理解”。
- 至少 4/5 名参与者能找到并继续未完成的理解。
- 至少 4/5 名参与者能理解“阶段性理解可继续修正”。
- 0 人将系统理解明确认为医疗诊断或确定性人格结论。
- 不出现 P0 问题；P1 问题需有明确修复方案。

## 10. 测试后动作

1. 汇总共性问题，按 P0 / P1 / P2 分类。
2. 只修复影响核心路径和心理安全的 P0、P1 问题。
3. 更新 PRD 的交互状态和文案。
4. 将通过的流程冻结为 MVP V1，进入数据结构、AI 状态机和隐私方案设计。
5. 测试记录去标识化保存，不将参与者真实梦境写入产品演示数据。
