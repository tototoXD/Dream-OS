# Dream OS MVP 主流程验收清单 v1.0

版本：2026-08-05  
范围：移动端点击原型 `05_UX/prototype/index.html`  
目标：验证从记录梦境到形成一次阶段性理解的最小闭环，确认每个状态都可被用户看懂、可继续、可退出。

## 1. 验收规则

- 每条用例都需要在原型中实际操作一次，并记录结果：通过 / 失败 / 待确认。
- “通过”不仅代表按钮可点击，还需要确认页面状态、文案和数据状态同时正确。
- 所有心理相关文案必须保持“阶段性、可修正、非诊断”的边界。
- 验收时分别覆盖：首次记录、已有历史记录、当天补充、已完成理解、删除梦境。

## 2. 核心状态

| 状态 | 含义 | 用户可见结果 |
|---|---|---|
| `IDLE` | 尚未开始记录 | 首页引导文案与“记录梦境”按钮 |
| `DRAFT` | 便签中有未保存内容 | 时间、原始内容、返回、保存按钮 |
| `SAVED_RECORD_ONLY` | 已归档但尚未澄清 | Dreams 有记录；理解页显示“开始澄清” |
| `UNDERSTANDING_IN_PROGRESS` | 正在进行一次理解会话 | AI 对话、问题顺序、回答输入 |
| `UNDERSTOOD_ONCE` | 已完成一次澄清 | 不重复显示澄清入口；理解页显示最近理解 |
| `SUPPLEMENT_PENDING` | 已理解梦境又产生补充 | 同一 Dream Record 进入新版本理解 |
| `DELETED` | 用户确认删除 | Dreams、日历与关联证据同步移除 |

## 3. P0 核心闭环

### A. 首页 → 梦境便签

- [ ] **A-01 初始首页**  
  预期：显示早上好引导、记录提示和一个“记录梦境”悬浮按钮；不显示键盘图标、最近梦境或复杂状态模块。

- [ ] **A-02 进入便签**  
  操作：点击“记录梦境”。  
  预期：引导文案隐藏，便签出现；标题为空；时间立即显示；文字输入框自动获得焦点并吊起键盘；光标位于便签正文顶部；右下角显示麦克风按钮。

- [ ] **A-03 文字记录**  
  操作：输入一个词、一句话和多行文字。  
  预期：内容实时写入便签原文；光标跟随文字末尾；输入为空时不显示保存按钮；出现有效文字后显示便签外部的“保存梦境记录”。

- [ ] **A-04 语音记录**  
  操作：点击麦克风开始，再次点击结束。  
  预期：状态变为“语音记录中”；语音转写追加到同一张便签；结束后可以继续打字；保存按钮只在产生有效转写后出现。

- [ ] **A-05 返回草稿**  
  操作：输入内容后点击左上角“返回”，再次进入记录梦境。  
  预期：草稿仍在本地，不进入 Dreams、不显示在历史列表；用户可以继续编辑或明确放弃草稿。

- [ ] **A-06 保存归档**  
  操作：点击“保存梦境记录”。  
  预期：保存前才生成描述性标题；便签收起到 Dreams；不显示额外红点；动画结束后自动进入理解页，不返回首页。

### B. Dreams 历史

- [ ] **B-01 原样记录**  
  预期：Dreams 显示标题、完整年月日时间和原始记录；AI 理解不覆盖原文。

- [ ] **B-02 当天与历史权限**  
  预期：当天梦境可显示“补充梦境”；历史梦境不显示补充入口。

- [ ] **B-03 已理解状态**  
  预期：完成一次理解后，该梦显示“已完成一次理解”状态，不重复显示“开始澄清”入口。

- [ ] **B-04 日历同步**  
  预期：有梦日期显示圆点；点击日期只展示当天梦境；删除后圆点同步消失。

- [ ] **B-05 长按删除**  
  预期：长按约 500ms 才打开确认层；确认后同步移除历史卡、日历索引和可撤销的关联证据；轻触、滚动和补充按钮不得误触。

### C. 理解页与理解会话

- [ ] **C-01 初始理解页**  
  预期：不是空白页；先显示近期状态整理、证据数量和最新梦境；未完成的梦显示“开始澄清这个梦”。

- [ ] **C-02 首个问题自动选择**  
  操作：点击开始澄清。  
  预期：不要求用户先选择理解焦点；AI 根据梦境最明确线索直接发出第一个问题。

- [ ] **C-03 对话输入统一**  
  预期：选项点击、自由文字、语音回答都进入同一条 Understanding Session；一次只出现一个问题。

- [ ] **C-04 理解草稿生成**  
  预期：达到问题门槛后出现“查看当前理解草稿”；生成的内容包含观察、可能理解和仍不确定，并明确不是定论；此时不得标记梦境为“已完成一次理解”。

- [ ] **C-05 用户确认后完成理解**  
  操作：在当前理解草稿中选择“很贴近”并提交。  
  预期：只有此时最新区域显示“最近理解”；不再显示澄清按钮；Dreams 对应卡显示“已完成一次理解”。

- [ ] **C-06 拒绝或部分确认不完成**  
  操作：选择“部分贴近”“不太像”或“还不能判断”。  
  预期：梦境保持未确认状态，不进入稳定理解历史；用户可以继续修正或稍后处理。

- [ ] **C-07 近期状态更新**  
  预期：更新时间变为“刚刚”；确认内容、相关梦境数量或证据数量发生对应更新；新理解可追溯到本次梦境与用户回答。

### D. 补充与版本

- [ ] **D-01 已理解梦境补充**  
  操作：对已完成理解的当天梦境点击“补充梦境”，增加新内容并保存。  
  预期：原始记录更新但不重复创建 Dream Record；状态进入 `SUPPLEMENT_PENDING`；重新开放新一版理解。

- [ ] **D-02 历史梦不可补充**  
  预期：非当天历史梦不能通过 Dreams 卡片补充；原有理解仍可只读查看。

## 4. P1 内容与安全检查

- [ ] **E-01 证据边界**：没有足够证据时只记录，不强行输出心理结论。
- [ ] **E-02 用户控制权**：用户可以稍后理解、暂停会话、拒绝或部分确认。
- [ ] **E-03 原始数据分层**：原始文字、转写和语音引用不被 AI 摘要覆盖。
- [ ] **E-04 删除影响说明**：删除梦境前明确提示相关理解和图谱证据会受到影响。
- [ ] **E-05 图谱解释来源**：每个节点的“对你目前可能意味着”都能回到具体梦境、回答或用户确认。

## 5. 当前优先修正项

验收第一轮建议优先关注以下三项：

1. **A-05**：返回后草稿能否恢复，或是否明确提供放弃草稿的动作。
2. **B-03 / C-05**：已完成理解的梦是否彻底移除重复澄清入口。
3. **D-01**：补充已理解梦境后，是否重新开启下一版理解，而不是继续沿用旧状态。

验收记录完成后，再进入视觉细节、无障碍和真实用户测试。
