# Dream OS Page-Level Wireframe Spec v1.0

## MVP 页面结构、组件、状态与交互规范

**适用平台：** iOS / Android 移动端  
**上游文档：** `Dream_OS_PRD_v1.2.md`、`Dream_OS_Analysis_Readiness_Evaluation_Spec_v1.0.md`  
**目标：** 把梦境记录、Analysis Readiness、Understanding Session 和长期理解转化为可设计、可开发、可验收的页面。

---

## 0. 设计原则

1. **先接住，再分析：** 保存成功必须先于 AI 解释。
2. **原话与 AI 分层：** 用户原话、AI 观察、AI 假设不能使用相同视觉样式。
3. **不分析也是完整结果：** `RECORD_FIRST` 具有明确完成态，不显示失败感。
4. **一次一个决定：** 每屏只保留一个主要任务和一个主按钮。
5. **用户随时能退出：** 会话中始终提供跳过、稍后继续、不想谈或结束。
6. **证据可见：** 心理假设必须能展开查看支持材料和历史引用。
7. **不展示伪精确分数：** 不向用户显示 Analysis Readiness 百分比或心理概率。
8. **信息最小化：** 默认页只呈现当前决定所需的信息；解释、证据和完整原文按需展开，不把产品规则写成长段说明。

## 1. MVP 信息架构

底部导航收敛为四项：

```text
首页        梦境        理解        梦图谱
首页         梦境           理解                  我的
```

`Settings` 作为 `Me` 的二级页面，包含隐私、语音、历史引用、长期建模、导出和删除。录梦采用全局浮动主操作，不占一级导航。

## 2. 全局组件与视觉语义

### 2.1 内容来源标签

| 来源 | 标签 | 视觉建议 |
|---|---|---|
| 用户原话 | `你记录的` | 中性实色卡片 |
| 用户补充 | `你补充的` | 同色浅底，显示时间 |
| AI 事实观察 | `我们观察到` | 冷灰描边卡片 |
| AI 阶段性假设 | `一种可能的理解` | 柔和强调色，始终带“可能” |
| 用户确认 | `你确认贴近` | 明确确认标记 |
| 反证 | `你说这不符合` | 中性删除线或反证标签，不用错误红 |
| 历史引用 | `参考了过去的梦` | 可点击引用条，显示日期和片段 |

### 2.2 通用状态

所有异步页面必须具有：`loading / success / empty / offline / retryable_error / permission_denied / deleted`。Loading 文案描述动作，例如“正在整理你的记录”，不得写“正在解读你的潜意识”。

### 2.3 主次按钮

- 每屏最多一个 filled primary button；
- secondary 使用 outline 或 text；
- “只记录”“稍后继续”与“现在理解”必须是同等尊重的选择，不用警告色弱化；
- 删除、清空模型等不可逆操作必须二次确认并说明影响范围。

## 4. P02 Home

```text
toto
还记得刚才的梦吗？

记录不必完整，一个词、一种感觉、一个画面也可以。

[记录梦境]

点击键盘图标后，同一位置切换为：

[写下刚才的梦…] [麦克风图标]

首页  梦境  理解  梦图谱
```

MVP Home 永远保持这一结构，不根据数据量增加最近梦境、理解摘要或持续观察模块。引导文案位于页面视觉中部。底部导航上方只保留一个居中悬浮的紧凑胶囊按钮“记录梦境”，不显示键盘或其他并列入口。点击后进入便签记录状态，底部在原位置展开类似对话产品的统一输入器：默认是文字输入框，右侧提供麦克风入口。

首页左上角另有一个仅含菜单/历史图标的入口。点击后打开“理解历史”抽屉，抽屉内显示账号摘要（昵称、个人空间、梦境数量、已完成理解次数）以及最近完成和历史 Understanding Session。只有完成过一次理解的会话才进入这里；未完成理解仍从 `Understanding` tab 进入。该抽屉只承载 AI 理解会话索引，不重复展示 `Dreams` 的原始梦境正文。

点击抽屉中的会话进入独立的“理解记录”详情页。详情页左上角只显示返回箭头图标；点击后回到“理解历史”抽屉。详情页展示关联梦境、会话状态、AI 问题、用户回答、理解草稿、用户反馈和证据来源；必须优先展示真实会话轨迹，不能用固定摘要替代历史对话。未完成会话不进入该抽屉。

### 4.1 Home 内记录状态

- 点击“记录梦境”：进入便签记录状态，自动聚焦默认文字输入框并吊起键盘；便签顶部显示等待输入的光标；
- 点击输入器右侧麦克风：开始语音输入；再次点击结束本段语音并写入同一条便签；
- 用户输入有效文字或结束一段有效语音后，便签卡片外部出现小尺寸“保存”按钮；无内容时不显示；
- 保存按钮是页面操作，不属于便签内容，不得放在便签卡片内部；
- 两种语音交互都不跳转页面；
- 开始录音或开始打字后，中部引导文案隐藏，原位置出现一张梦境记录便签；文字输入光标固定跟随便签正文起始位置与当前文字末尾；
- 语音转写或键盘文字持续写入便签，便签是当前 Dream Record 的即时草稿；
- 便签页顶部显示简洁标题“记录梦境”；
- 便签只保留记录时间（格式为“YYYY年M月D日 HH:mm”），不显示“记录于”前缀，也不显示右侧记录状态；
- 用户可以继续录音或切换为文字补充，内容追加到同一条记录。
- 记录状态在页面左上角提供仅含返回箭头图标的按钮（保留无障碍标签，不显示“返回”文字），不放在梦境便签内部；返回只退出便签视图并保留本地草稿，不归档、不删除内容；
- 用户再次开始语音或文字输入时恢复同一张便签；
- 语音录制尚未发送时不显示“保存”按钮；完成松手发送或点击发送后，保存按钮才出现；
- 文字输入产生有效内容后可以显示保存按钮；
- 用户点击保存后，系统根据梦境内容生成简短、描述性且不带心理解释的标题，例如“无法抵达的 B2”；
- 自动标题只用于识别记录，不得包含诊断或象征结论；用户继续追加内容后，便签重新进入待保存状态。
- 保存完成后，该 Dream Record 归档到 `Dreams`；再次保存同一便签时更新原记录，不创建重复项。
- 点击“保存”后，便签以缩小并移动到 `Dreams` 底部导航位置的收起动画确认归档；动画结束后进入“梦已经保存”确认页，不自动开始理解。确认页直接展示同一张梦境便签并询问“现在开始理解吗？”，提供主按钮 `[现在理解]` 和无边框文字链接 `[只保存，不解梦]`；用户选择前不得创建 Understanding Session。
- 归档完成后不增加额外红点；收起动画和“梦已保存”确认页已经足够表达保存成功。开启“减少动态效果”时使用短淡出替代完整位移动画。
- 用户进入 `Understanding` 后，页面先展示近一段时间的阶段性心理状态整理：反复记录到的体验、用户已确认的理解、仍在观察的关系及其证据状态；随后展示最新梦境并邀请用户“开始澄清这个梦”。只有用户主动选择后才进入理解流程；选择“稍后再说”保留待理解状态。未完成会话离开后自动保存，并收纳到首页的理解历史入口，用户从那里继续。
- 用户选择“现在开始”后不再进入“选择理解焦点”页面。系统根据梦境中最明确、最接近直接体验的线索自动选择第一个问题，并在问题卡中说明该问题来自本次梦境原文。后续问题按“确认体验 → 关键时刻 → 现实背景”的顺序逐题显示；一次只显示一个问题，用户回答或跳过后进入下一题。
- “理解这个梦”采用 AI 对话界面。AI 通过消息依次发送观察、问题和可直接回答的选项；用户点击选项后，该选项立即作为用户消息发送。底部常驻统一回复栏，用户也可自由打字发送，或通过麦克风录入语音回答。选项、文字和语音统一写入本次 Understanding Session，不形成三套流程。AI 每收到一次回复后再发送下一问，信息足够后在对话中提供“查看当前理解”。
- 一条梦完成一次 Understanding Session 后，系统先生成理解草稿；只有用户明确选择“很贴近”并提交反馈，Dream Record 才标记为“已完成一次理解”，进入理解历史并停止显示“开始澄清”入口。“部分贴近”“不太像”“还不能判断”均保持未确认状态；后续只有用户补充了新材料，才创建新的理解版本并重新开放继续理解。
- Understanding 完成后，近期状态整理立即更新：更新时间改为刚刚，相关确认内容与证据数量同步增加；最新梦境区域改为展示“最近理解”，不再显示澄清按钮。
- 保存完成后隐藏便签内的“返回”按钮，后续通过 `Dreams` 查看已归档记录。

### 4.2 Dreams 原始记录归档

`Dreams` 保存用户历史上所有已保存的梦境原样记录。列表卡片包含：

- 自动生成或用户修改后的标题；
- 完整记录时间，格式为“YYYY年M月D日 HH:mm”；
- 标记为“原样记录”的用户语音转写与键盘内容；
- 原始语音入口（存在语音时）。

每个 Dream Record 只使用一张统一的便签卡片，不在卡片下方添加叠层、错位纸张或多卡阴影。首页记录、Dreams 历史、日历结果和 Understanding 中出现同一条梦时，保持相同的便签背景、边框、轻微倾斜和时间标签；标题是卡片最高信息层级，原样记录紧随其后。AI 状态和心理理解使用独立的普通信息卡，不与梦境便签混用。

列表按记录时间倒序排列，并支持连续纵向滚动。仅当天创建的梦境卡片在右上角提供“补充梦境”；点击后回到 Home 的同一条 Dream Record 便签，保留原有标题与记录时间。用户追加内容并保存时更新原记录，不创建重复卡片。跨日后的历史梦境不再提供补充入口，只保留原样记录查看。

用户长按任意梦境卡片约 500ms 后打开删除确认层。确认层必须显示梦境标题，并明确说明删除不可撤销；只有用户再次点击“删除梦境”才执行删除。轻触、纵向滚动或在“补充梦境”按钮上按压不得触发删除。删除后同步更新 Dreams 列表、日历日期圆点以及该梦境关联的理解和图谱证据。

页面右上角提供日历图标。点击后进入独立的“梦境日历”页面，左上角提供仅含返回箭头图标的按钮返回 `Dreams`。有梦境记录的日期在日期数字下方显示圆点；点击有记录的日期后，在月历下方展示当天全部梦境卡片。无记录日期不可进入详情。日历标记只表示“当天有记录”，不表达分析状态或梦境数量。

当前可点击原型预置一套以 `toto` 第一人称书写的三个月模拟数据：2026 年 6 月至 8 月共 30 条梦境，保持每周约 2–3 条的非均匀记录频率。该数据仅用于验证历史滚动、跨月日历、长按删除和梦图谱聚合，不代表用户的真实经历或心理结论。

AI 的结构化观察、心理假设和长期模式不得改写或替换原样记录。理解结果通过 Dream Detail 的独立区域关联展示。

- 未完成会话：`Understanding` 标签显示小提示点，进入后置顶“继续上次理解”；
- 最近梦境：只在 `Dreams` 列表展示；
- 最近理解、候选模式与正在观察：只在 `Understanding` 展示；
- 语音和键盘：共用同一个底部记录栏，在原位置切换输入状态，后台创建同一种 Dream Record；
- 没有未处理事项时，所有导航标签不显示提示点。

## 5. P03 Dream Capture

Dream Capture 是单一记录容器。语音和键盘不是两种记录类型；用户可在同一条 Dream Record 中随时切换，内容长度与完整性不影响保存资格。

### 统一记录页

```text
取消                              保存

[记录内容区域]
不必从头讲，也不用讲完整。
记得什么，就先留下什么。

[键盘输入区域 / 当前语音转写草稿]

[麦克风]                         [键盘]
```

默认根据用户最后使用方式或当前键盘状态呈现，但不要求先选择模式。点击麦克风开始录制；点击键盘进入文字输入。用户从语音切换到键盘时，录音暂停，已产生内容仍属于当前记录。

### 语音输入状态

显示录音时间、波形、暂停和完成。录制时不显示 AI 分析、不提问；为避免用户分心，实时转写可不展示，暂停后再显示可编辑转写。上传失败时保留本地加密录音，显示“已安全保存在本机，联网后继续上传”。

### 键盘输入状态

编辑器自动保存草稿；键盘上方仅提供麦克风切换、添加醒后感受和保存。不得用结构化表单打断回忆。

### 保存规则

- 空内容不能保存；存在任意文字或有效录音即可保存；
- 不设置最小字数、最低录音时长或“完整梦境”选项；
- “片段”只是内容状态，不是数据类型；系统可在后台判断材料有限，但不能让用户重新选择记录类型；
- 同一次记录中的语音、转写和键盘补充共同归属于一条 Dream Record，并分别保留来源。

## 6. P04 Save Confirmation

```text
梦已保存

现在开始理解吗？

[便签：标题 / 日期与时间 / 原样记录]

[现在理解]
只保存，不解梦
```

保存成功即创建 DreamRecord，并直接展示同一条梦境便签。用户明确选择后才创建 Understanding Session；完整原文和证据仍保留在便签与后续详情页中。主按钮为“现在理解”，次要操作使用无边框文字链接“只保存，不解梦”。

## 7. P05 Dream Detail

页面顺序固定为：标题与日期 → 原始记录 → 用户补充 → 当前状态 → 理解结果 → 版本与管理。

- 原始语音提供播放、导出、删除语音；
- 编辑原始文本时保留版本，明确区分“修正转写”和“新增补充”；
- `PROCESSING_FAILED` 显示重试和手动整理，不丢失原始记录；
- 删除语音时说明文字记录仍保留；删除整条梦时显示依赖理解将被重评。

## 8. P06 Readiness Result

### 8.1 `ANALYSIS_READY`

**标题：** “现在开始理解吗？”<br>
**信息：** 梦境标题 + 日期与时间。<br>
**操作：** `[现在理解]` + 无边框文字链接 `[只保存，不解梦]`

分析边界和证据在理解详情页按需展开；不在保存确认页预先堆叠说明。

### 8.2 `NEEDS_CLARIFICATION`

**标题：** “再补充一点，可能会更清楚”  
一次显示一个问题，最多两个；提供 `[回答] [跳过并记录] [稍后再说]`。回答后显示“重新判断中”，不能提前展示心理假设。

### 8.3 `RECORD_FIRST`

**标题：** “这次先完整记录下来”  
**说明：** “目前的信息还不足以形成可靠的心理分析。以后出现相似梦境，或你想起相关感受和背景时，我们可以重新看看。”  
**操作：** `[完成] [补充新信息]`。不提供“仍然分析”按钮。

### 8.4 `BODY_CONTEXT_FIRST`

**标题：** “先把身体背景记录下来”  
**说明：** “梦里的感受可能首先受到现实身体状态、药物或环境影响。我们不会把它直接解释成心理象征。”  
**操作：** `[补充身体背景] [先保存]`。不得给医疗诊断或紧迫性判断。

### 8.5 `SAFETY_REVIEW`

立即跳转 P13；不展示路由名、不继续梦境分析、不保留戏剧化梦境图像作为背景。

这次你想先理解哪一部分？
一次只选一个，之后可以再回来。

## 10. P08 Understanding Session

```text
←                 ━━━━━━━

在梦里，你知道车应该在 B2，却一直找不到；电梯里也没有 B2 这个按钮。
回到那个瞬间，哪一种感受最接近你？

[着急       很想尽快找到车或出口，但越找越来不及。          ○]
[困惑       方向似乎知道，却无法确认下一步该怎么走。      ○]
[被卡住     明明有目的地，却没有可以继续的入口。          ○]
[害怕       担心继续走下去，会发生不好的事。              ○]
[说不清     记得画面，但现在还无法判断当时的感受。        ○]
[输入回答]
```

- 一屏一问，不显示造成压力的“还剩 4 题”；
- 顶部只显示轻量进度条，不显示“AI 问题”标签或额外阶段卡片；
- AI 与用户内容采用聊天流，不用卡片包裹 AI 文本；
- 选项采用纵向单列表单，每行包含主选项、帮助理解的补充描述和右侧选择器；点击整行即选中并发送；
- 历史引用出现时先显示引用内容，再提出问题；
- “不想谈这个”后禁止同义追问；
- 离开时自动保存位置、回答和跳过主题；未完成会话进入首页理解历史，可从上次位置继续。

## 11. P09 Understanding Draft / Current Understanding

Understanding 中的待理解梦境必须复用保存确认页的同一张便签：标题、时间和原样记录保持不变，只根据上下文显示“开始理解”或“继续理解”操作，不重新改写成另一种摘要卡片。

```text
这次梦，我先这样理解

你一直知道要去 B2，
却怎么也到不了。

这可能和你最近“知道方向，却推进不了”的感觉有关。

“车应该在 B2，但电梯里没有这个按钮。”
来自你的梦境记录

“知道方向，却推进不了。”
来自你刚才的回答

还不确定：
B2 和车对你个人意味着什么。 继续讨论 >

贴近你的感受吗？
[很贴近]
不太像   补充
```

默认只显示一条核心理解和一条不确定信息。MVP 的依据较短，直接用引用文案呈现梦境片段和用户回答，不增加“查看依据”入口；未来证据超过两条时再折叠更多内容。“还不确定”提供轻量“继续讨论”文字入口。首屏最多保留三个行动项：“很贴近”“不太像”“补充”。点击“补充”后在当前草稿下展开聊天流，不跳转页面；AI 用自然语言直接说明用户可以补充梦境细节、修正理解或说明现实联系，不再提供三组选项。对话中用内联文字“重新整理这次理解”返回草稿，不显示“完成补充”大按钮。默认不出现“写入长期模型”等技术语言。

## 13. P11 Understanding Archive

顶部筛选：`全部 / 已确认 / 待验证 / 开放问题 / 已修正`。

列表卡显示标题、最近更新时间、状态、支持梦境数量。详情页显示版本时间线、支持证据、反证和用户修正。被替换版本仍可查看，但明确标记“旧版本，不再用于当前理解”。Understanding Archive 不构建人格雷达图；轻量关系图谱集中在 `Me` 展示。

## 14. P12 Me & Settings

`Me` 的首屏核心模块为“我的梦境图谱”，而不是设置列表。图谱以用户梦中反复出现的个人意象为中心节点，连接四类信息：共同出现的地点或人物、重复情节、伴随感受、个人理解或现实议题。

MVP 图谱要求：

- 默认展示约 8–15 个高频节点，必须包含多个反复出现的意象，而不是只呈现出现次数最高的一个。首版示例包括车、房子 / 房间、水 / 海、学校 / 考试、电梯 / 楼层、火车 / 站台、道路 / 出口，以及连接它们的重复体验；
- 图谱必须是多节点互联网络，而不是中心节点的单层树状菜单。当前选中节点可以居中突出，但其他节点之间仍按实际共现、情节或已确认关系互相连线；例如“车 → 寻找 / 迷路”，同时存在“道路 / 出口 → 寻找 / 迷路”；
- 节点大小可表达出现频率，但不得表达人格强弱、疾病风险或心理严重程度；
- 连接必须区分“记录事实”“用户已确认”“正在观察”；AI 候选不得伪装成已确认关系；
- 每一个图谱节点都可点击进入统一的节点详情页，不限于当前中心意象。详情页展示出现次数、最近出现、常见连接、证据状态、依据和全部相关梦境；只有用户已确认的节点使用“对你目前可能意味着”，记录事实节点使用“目前能说的”，正在观察节点使用“正在观察的可能联系”。所有描述必须引用用户记录与确认，使用“可能”并允许修正，不得作为固定象征词典解释；
- 不提供固定象征词典结论，不输出“车通常象征控制”等通用断言；
- Settings 收入 `Me` 的二级入口，避免与个人图谱争夺首屏注意力。

首个原型节点为“车”：连接“地下停车场”“寻找 / 迷路”“着急”“下沉”等记录事实，“无法抵达”为用户已确认关系，“工作推进”为正在观察关系。

三个月模拟数据中，“车”在 8 条梦境里出现。节点详情列出全部 8 条相关记录；图谱首页基于全部 30 条梦境聚合高频意象和关系，而不是只读取当前月。

### 14.1 Settings 分组

分组：

1. **你的数据：** 导出全部数据、语音保留说明、存储使用情况；
2. **AI 如何使用历史：** 历史引用开关和示例；关闭后新会话不使用历史，既有引用仍可追溯；
3. **长期理解：** 暂停长期建模、清空个人理解；暂停不影响继续记录梦；
4. **删除：** 删除全部数据；展示即时不可用、主存储 7 天和灾备 30 天清除说明；
5. **关于：** 产品边界、非医疗诊断说明、隐私政策。

### 14.2 长期建模控制文案

- 暂停：“继续记录梦，但不再形成或更新长期模式。”
- 清空：“删除候选模式和个人理解，保留原始梦境。你之后可以重新开始。”
- 删除全部：“删除梦境、语音、回答和理解记录。此操作不可撤销。”

## 15. P13 Safety Hold

页面目标是把关注点从梦的象征转向用户当前现实状态。

```text
先确认你现在是否安全

你刚才提到的内容可能关系到现实中的安全。
我们先不继续分析这个梦。

[我现在处于立即危险中]
[我现在安全，但需要支持]
[这不是现实意图 / 我想修正记录]
```

MVP 不建立国家级危机资源数据库，但必须：停止分析、允许用户修正误判、建议联系当地紧急服务或可信赖的人，并保存不含额外推断的安全事件。不能用梦境语言淡化用户的现实陈述。

## 17. MVP 埋点

仅记录产品事件和状态，不记录梦境正文：

- `capture_started / capture_saved / capture_abandoned`；
- `readiness_route_shown`，附 route 和版本，不附内容；
- `clarification_answered / skipped`；
- `session_started / paused / resumed / closed`；
- `understanding_feedback_submitted`；
- `partial_claim_selected / rejected / uncertain`；
- `history_citation_opened`；
- `modeling_paused / cleared`；
- `export_requested / deletion_requested / deletion_completed`。

## 18. 页面级验收标准

- [ ] 用户可在 60 秒内保存第一条梦境片段；
- [ ] 录音过程中没有提问或分析；
- [ ] 五种 Readiness 路由都有独立页面反馈；
- [ ] RECORD_FIRST 没有绕过分析按钮；
- [ ] 用户原话与 AI 假设在视觉和标签上可区分；
- [ ] 每条假设能展开查看证据；
- [ ] 历史引用在使用前后都有清晰感知；
- [ ] 离开会话后可从首页理解历史继续，“不想谈”会被尊重；
- [ ] 部分符合必须逐条选择；
- [ ] 删除、暂停和清空模型的影响范围清楚；
- [ ] 安全状态立即停止梦境分析；
- [ ] 所有错误态都保留原始记录。
